# Krushant's 2025 New Years Party - RSVP Website
## Requirements Document

---

## 1. Executive Summary

This document outlines the functional and technical requirements for the RSVP website developed for Krushant's 2025 New Years Party. The application provides a simple, user-friendly platform for guests to submit their RSVP status and view their submitted information.

**Project Name:** Krushant's RSVP Website  
**Event:** Krushant's 2025 New Years Party  
**Launch Date:** November 2025  
**Target Users:** Party Guests  
**Tech Stack:** React.js, Node.js, PostgreSQL, Render  

---

## 2. Business Requirements

### 2.1 Project Goals
- Provide an easy way for guests to confirm attendance
- Collect accurate guest count for party planning
- Allow guests to view their submitted RSVP
- Maintain data integrity and privacy

### 2.2 Scope
The application consists of three main pages:
1. Home page with navigation
2. Submit RSVP page with form
3. View RSVP page with lookup functionality

### 2.3 Success Criteria
- Website is accessible and user-friendly
- All RSVPs are successfully stored in database
- Guests can submit and retrieve their RSVP
- Zero data loss during party
- Website is live 2 weeks before event

## 4. Functional Requirements

### 4.1 Home Page
**Description:** Landing page with navigation options

**Requirements:**
- Display event title: "Krushant's 2025 New Years Party"
- Display invitation message
- Provide two main buttons:
  - "Submit RSVP" button
  - "View RSVP" button
- Responsive design for mobile devices
- Navigation bar with links to all pages

### 4.2 Submit RSVP Page
**Description:** Form page for guests to submit their RSVP

**Form Fields:**
1. **First Name** (Required, Text)
   - Max 100 characters
   - Validation: Non-empty

2. **Last Name** (Required, Text)
   - Max 100 characters
   - Validation: Non-empty

3. **Email Address** (Required, Email)
   - Validation: Valid email format
   - Unique constraint (one RSVP per email)
   - Max 255 characters

4. **How Many People Will Join You?** (Required, Dropdown)
   - Options: 0, 1, 2, 3, 4, 5
   - Default: 0
   - Validation: Must be in range 0-5

5. **Will You Join Us?** (Required, Dropdown)
   - Options: Yes, No
   - Default: Yes
   - Validation: Must be Yes or No

**Functionality:**
- Client-side validation before submission
- Server-side validation before database save
- Error messages for invalid input
- Success message after submission
- Clear button to reset form
- Submit button disabled during submission

**Error Handling:**
- Display "This field is required" for empty required fields
- Display "Valid email is required" for invalid email
- Display "This email has already submitted an RSVP" for duplicate email
- Display "Number of guests must be between 0 and 5" for invalid guest count
- Display "Please select Yes or No for RSVP" for invalid RSVP status

### 4.3 View RSVP Page
**Description:** Lookup page for guests to view their submitted RSVP

**Form Fields:**
1. **Email Address** (Required, Email)
   - Validation: Valid email format
   - Used to search database

**Functionality:**
- Accept email address input
- Search database for matching RSVP
- Display all RSVP details if found
- Display error message if not found

**Display Fields (if found):**
- First Name
- Last Name
- Email Address
- Number of Guests
- RSVP Status (Yes/No)

**Error Handling:**
- Display "Please enter an email address" if field is empty
- Display "Please enter a valid email address" for invalid format
- Display "Email address not registered for this event" if not found

## 5. Technical Requirements

### 5.1 Frontend (React.js)
**Technology:** React.js with Bootstrap  
**Framework:** React Router for navigation  
**HTTP Client:** Axios for API calls  

**Components:**
- Home.js - Landing page
- SubmitRSVP.js - RSVP submission form
- ViewRSVP.js - RSVP lookup page
- App.js - Main component with routing

**Features:**
- Responsive Bootstrap design
- Client-side form validation
- Real-time error display
- Success/error alert messages
- Mobile-friendly interface

**Browser Support:**
- Chrome (latest)
- Safari (latest)
- Firefox (latest)
- Edge (latest)
- Mobile browsers

### 5.2 Backend (Node.js)
**Framework:** Express.js  
**Port:** 5000 (local), 8080 (production)  
**Database Driver:** pg (PostgreSQL client)  
**ORM:** Sequelize  

**API Endpoints:**
1. `POST /api/rsvp/submit`
   - Request: JSON object with RSVP details
   - Response: Success message or error
   - Validation: Server-side validation

2. `POST /api/rsvp/lookup`
   - Request: Email address
   - Response: RSVP details or error message
   - Error: 404 if email not found

3. `GET /api/health`
   - Request: None
   - Response: Status message
   - Purpose: Health check endpoint

**Error Handling:**
- Return appropriate HTTP status codes
- Provide descriptive error messages
- Log all errors
- Handle database connection failures
- Handle validation errors

### 5.3 Database (PostgreSQL)
**Database Name:** krushant_rsvp_db  
**User:** postgres  

**Table: rsvps**

| Column | Type | Constraints |
|--------|------|-------------|
| id | SERIAL | PRIMARY KEY, AUTO_INCREMENT |
| first_name | VARCHAR(100) | NOT NULL |
| last_name | VARCHAR(100) | NOT NULL |
| email | VARCHAR(255) | UNIQUE, NOT NULL |
| number_of_guests | INTEGER | CHECK (0-5), NOT NULL |
| rsvp_status | VARCHAR(10) | CHECK ('Yes' or 'No'), NOT NULL |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP |
| updated_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP |

**Constraints:**
- Email must be unique (one RSVP per email)
- Number of guests must be 0-5
- RSVP status must be 'Yes' or 'No'
- All fields are required

## 8. Deployment Requirements

### 8.1 Hosting Platform
**Chosen Platform:** Render.com  
**Alternatives Considered:** Azure, Railway, Vercel, DigitalOcean

**Justification:**
- Simple deployment process
- Native PostgreSQL support
- Free tier available for testing
- Good documentation
- Cost-effective ($7-14/month for production)

### 8.2 Deployment Configuration
- Frontend: Static Site on Render
- Backend: Web Service on Render
- Database: PostgreSQL on Render
- SSL Certificate: Automatic (HTTPS included)
- Domain: Optional custom domain support

### 8.3 Environment Variables

**Local Development:**
```
PORT=5000
NODE_ENV=development
DATABASE_URL=postgresql://postgres@localhost:5432/krushant_rsvp_db
```

**Production (Render):**
```
PORT=8080
NODE_ENV=production
DATABASE_URL=postgresql://username:password@hostname:5432/krushant_rsvp_db
```
